3.1 Payroll Admin Lock Dual-Auth Test

1) As User A (admin/manager), request an admin lock:
   - Login as user A.
   - Call: POST /api/payroll-periods/{periodId}/request-admin-lock
     with a JSON body containing a reason.
   - Record:
     - Response JSON
     - Current DB state for that period (lock_status, lock_requested_by, lock_dual_auth_request_id, etc.)

2) While still User A, attempt to approve the same lock:
   - Call: POST /api/payroll-periods/{periodId}/approve-admin-lock
     with the same requestId.
   - Expected:
     - Failure with SoD violation (self-approval blocked).

3) As User B (different manager/owner), approve the admin lock:
   - Login as User B.
   - Call: POST /api/payroll-periods/{periodId}/approve-admin-lock
     with the same requestId.
   - Expected:
     - Success.
     - Period status transitions from pending_admin_lock to locked/admin_locked.
     - locked_by = User B.

4) Save a short test log to:
   - docs/audit/time-payroll/tests-admin-lock-dual-auth.md
   including:
   - Which users you used (by role, not password)
   - API calls and outcomes
   - Final DB state (selected fields)

3.2 High-Value Timesheet Correction Dual-Auth Test

We want to prove that:
- Low-impact correction = single approver.
- High-impact correction (> threshold or on locked period) = second approver required.

1) Identify or create:
   - A test timesheet for a user.

2) LOW-impact correction:
   - Create a correction below the threshold (e.g. 30 minutes).
   - Approve as a supervisor/manager.
   - Expect:
     - requires_dual_auth = false
     - second_approved_by and second_approved_at are NULL
     - Correction applied successfully.

3) HIGH-impact correction:
   - Create a correction above the threshold (e.g. > 120 minutes) OR on a locked period.
   - First approver (supervisor) approves.
   - Try to finalize with only that single approval.
   - Expected:
     - System indicates second approval required (via status or error).
     - requires_dual_auth = true.
   - Then have a second manager/owner approve.
   - Expected:
     - second_approved_by and second_approved_at are set.
     - SoD enforced (second approver != requested_by and != first approver).

4) Save test results to:
   - docs/audit/time-payroll/tests-timesheet-corrections-dual-auth.md
   including:
   - Threshold used
   - Requests/responses (sanitized)
   - Relevant DB snapshots.
